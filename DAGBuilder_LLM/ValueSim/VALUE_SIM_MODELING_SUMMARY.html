入口位于 ValueSim/simulation/simulate_dag.py，依据 DAG 节点的 task_kind 进行解析，只给已有 DAG 节点补充时间和载荷字段，不改变 DAG 拓扑。

每个节点新增字段

duration_s
该节点估算耗时（秒）
flops
计算量（通信节点为 0）
payload_bytes
通信或 TP 内部载荷
value_sim_detail
模型细节：带宽、延迟、TP 切分、collective 步骤等

⚠️ 拓扑不变性检查

ValueSim 会验证仿真前后节点数和边数是否一致。若仿真过程改变了 DAG 拓扑，将直接报错。

3Control 节点

control 节点用于 DAG 起点、终点或控制依赖，不代表真实计算或通信。

duration_s   = 0
flops        = 0
payload_bytes = 0

4Forward / Backward 计算节点

使用 estimate_tp_compute(...) 建模，将一个 layer 视为 TP supernode：本地计算按 TP 切分，同时加入 TP 内部 collective 通信时间。

4.1 计算量估算

若配置中显式提供 value_sim_config.layer_forward_flops 则直接使用；否则按 Transformer layer 估算：

tokens = microbatch_size × seq_len
attention_flops = 8 × tokens × hidden_size × hidden_size
mlp_flops = 4 × tokens × hidden_size × ffn_hidden_size
forward_flops = attention_flops + mlp_flops

反向计算量使用倍率：

backward_flops = forward_flops × backward_flop_multiplier    （默认 2.0）

4.2 TP 切分后本地计算时间

sharded_flops = flops / tp_size （tp_compute_sharding_enabled == True） sharded_flops = flops （否则） effective_flops = device_peak_flops × compute_efficiency local_compute_s = sharded_flops / effective_flops

4.3 TP 内部通信

若 tp_comm_enabled = True，当前仅支持 ring 模型。

tp_activation_bytes = microbatch_size × seq_len × hidden_size × precision_bytes(tp)
local_payload_bytes = full_activation_bytes / tp_size
steps_per_collective = 2 × (tp_size - 1)
wire_bytes_per_collective = 2 × local_payload_bytes × (tp_size - 1) / tp_size

每个 collective 的通信时间：

duration_per_collective = steps_per_collective × latency_s + wire_bytes_per_collective / effective_bandwidth_bytes_per_s

总 TP 通信时间：

tp_comm_s = duration_per_collective × collective_count
节点类型collective_count
forwardtp_forward_collectives_per_layer
backwardtp_backward_collectives_per_layer

💡 跨亲和组 (Cross-Affinity) 链路

TP domain 跨 affinity group 时使用 tp_cross_affinity_link_type（通常走 RoCE）；否则使用 tp_intra_affinity_link_type（通常 HCCS / 节点内）。

4.4 Forward / Backward 最终 duration

tp_comm_non_overlapped_s = tp_comm_s × (1 - tp_comm_overlap_ratio) duration_s = local_compute_s + tp_comm_non_overlapped_s

5PP 通信节点

包括 pp_forward_send、pp_forward_recv、pp_backward_send、pp_backward_recv，统一使用 estimate_pp_p2p(...) 建模。

Payload 计算

pp_activation_bytes = microbatch_size × seq_len × hidden_size × precision_bytes(pp) / tp_size

链路类型

由 value_sim_config.pp_link_type 决定：

链路类型带宽来源延迟来源
roceRoCE 带宽RoCE 静态延迟
hccs / innodeHCCS / 节点内带宽节点内静态延迟
effective_bandwidth = bandwidth_gbps × 1e9 / 8 × utilization_ratio duration_s = latency_s + payload_bytes / effective_bandwidth

⚠️ Ascend 约束

validate_value_sim_config() 要求 Ascend profile 下 pp_link_type = roce，除非后续显式重新设计。

6DP 通信节点

DP 节点的 payload 通常来自当前 PP stage 的梯度大小。

6.1 DP Payload 计算优先级

  1. 若 DAG 节点显式带有 payload_bytes 或 bucket_bytes，优先使用；若未声明已 TP 切分则除以 tp_size
  2. 若节点有 pp_stage_id，按 stage 内层数计算梯度大小：
stage_gradient_bytes = num_layers_in_stage × layer_param_bytes / tp_size

6.2 单层参数量估算

attention_params = 4 × hidden_size × hidden_size
mlp_params = 2 × hidden_size × ffn_hidden_size
layer_param_count = attention_params + mlp_params
layer_param_bytes = layer_param_count × precision_bytes(dp)

若无 stage 信息，则退化为单层参数大小或配置中的 dp_bucket_size_bytes。

7DP ReduceScatter / AllGather

dp_reducescatter 和 dp_allgather 使用同一套分层 collective 模型（layered collective），仅 direction 不同。

模型输入参数

参数含义
domain_size= dp_size
ranks_per_node每节点 rank 数
affinity_group_size亲和组大小
HCCS 有效带宽节点内带宽
RoCE 有效带宽跨节点带宽
节点内 / RoCE 静态延迟链路延迟

三层分层结构

n1 = min(ranks_per_node, domain_size) n2 = min(affinity_group_size, ceil(domain_size / n1)) n3 = ceil(domain_size / (n1 × n2))

每个 rank 的基本数据量：

per_rank_bytes = total_data_size / domain_size

三层步骤数：

layer1_steps = n1 - 1            ← 节点内
layer2_steps = ceil(log₂(n2))    ← 亲和组内
layer3_steps = ceil(log₂(n3))    ← 跨节点 RoCE

每步数据量按 per_rank_bytes × 2^step 估算：

step_time = latency_s + step_bytes / bandwidth duration_s = sum(节点内) + sum(亲和组) + sum(跨节点 RoCE)

📝 详细记录

value_sim_detail.steps 会记录每一层、每一步的 payload、传输时间、静态延迟和 step duration。

8DP AllReduce

dp_allreduce 支持两类模式。

① 分层 / 分解路径 (hierarchical / decomposed)

当 allreduce_mode = decomposed 或 dp_collective_model = hierarchical 时：

duration_s = ReduceScatter(payload).duration_s + AllGather(payload).duration_s

不改变 DAG 拓扑，仅在 dp_allreduce 节点内部把时间分解为 RS + AG。

② 简单 Ring 路径

使用 ring alpha-beta 估算（当前走 HCCS 带宽和节点内延迟）：

steps = 2 × (dp_size - 1)
wire_bytes = 2 × payload_bytes × (dp_size - 1) / dp_size
duration_s = steps × latency_s + wire_bytes / effective_bandwidth

10当前模型假设与限制

#假设 / 限制
1ValueSim 不修改节点和边，只给节点加权
2Forward / Backward 是 layer 粒度节点，不是算子级节点
3TP 通信被合并进 compute 节点内部，不展开成独立 DAG 节点
4PP send/recv 当前使用同样的点到点通信模型
5DP stage-level 节点可能是 monolithic，也可能由 DagGenerator 直接生成 RS+AG 节点
6AllReduce 的 hierarchical 分解仅发生在 duration 估算内部，不会自动拆 DAG 节点
7当前仅支持已列出的 task_kind，新节点类型需要显式增加模型分发
8当前模型主要是解析式估算，不是基于真实 profiler trace 的逐算子仿真

📌 核心设计原则

ValueSim 定位为轻量级数值仿真层：基于解析公式快速估算 DAG 节点耗时，服务于搜索空间内的快速评估，而非取代 profiling。如需逐算子精确仿真，请结合真实硬件 trace 数据。
