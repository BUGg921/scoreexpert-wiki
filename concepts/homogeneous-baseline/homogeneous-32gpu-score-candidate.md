# 标准 32 卡基线选择经验草案

## Status

`unverified`。本页只能用于在严格匹配的 32 卡场景中生成待 Evaluation 的第一基线，不能作为已经证明更优的正式部署经验。当前证据解释的是 v10 score 为什么选择该组合，不是实际 latency 或 throughput 为什么更优。

## 经验分类

- 主分类：**同构基线**。
- 分类依据：当前场景无已知慢卡或异构设备，本经验用于建立正常 32 卡部署的第一验证基线。
- 目标总览：[[latency-first-experience-summary]]。

## 1. 要解决的决策

在来源给出的 32 卡同构场景和 v10 score 下，选择哪个 `PP/TP/DP/MBN` 组合作为第一轮 Evaluation 基线，并确定必须同时测试哪些反事实候选。

## 2. 一句话决策规则

**IF** 场景、候选约束和 score 均与本页“召回条件”一致，**THEN** 把 `PP=1,TP=8,DP=4,MBN=1` 作为第一基线，并至少同时测试 `4/8`、浅 PP 和少卡候选；**ELSE** 不复用 `8/4` 或 `2:1`，重新生成候选并运行搜索。

这条规则只负责“选验证基线”，不直接宣称“选真实部署最优解”。

## 3. 来源明确经验

原文件已经给出四条结论，按来源顺序和原有限定保留：

1. **满卡优先**：来源判断当前通信尚未成为主瓶颈，`idle` 损失大于通信优化收益，因此优先使用全部 32 张卡；同时建议通过仿真寻找结论反转的边界。
2. **TP 与 DP 接近平衡**：来源根据 score 认为 TP/DP 应接近平衡并略偏向 TP；在 `TP≤8` 和所列离散候选中选择 `TP:DP=2:1`，即 `TP=8,DP=4`。
3. **PP 倾向于 1**：来源认为 bubble 只有惩罚，因此用 `PP=1` 避免 pipeline bubble penalty。
4. **MBN 倾向于 1**：来源根据 `-0.5×(MBN-1)²` 在 1 处取 0，选择 `MBN=1`。

以上是来源结论；其跨场景有效性尚未由 Evaluation 证明。

## 4. 召回条件

### 必须满足

- GPU 总数为 32，每节点 8 卡，共 4 个节点。
- 每两个节点构成一个 16 卡亲和组；带宽层级为节点内最高、亲和组内跨节点次之、跨亲和组最低。
- 无已知慢卡或异构设备。
- 使用来源中的 v10 score，且相关系数和变量定义未改变。
- 候选满足 `PP×TP×DP=32`、`TP≤8`，并允许 `PP=1,TP=8,DP=4,MBN=1`。
- 当前目标是生成 Evaluation 基线，而不是跳过验证直接部署。

### 尚未证明可以变化

- 模型规模、层数、global batch 和显存压力。
- 网络带宽和时延的具体数值。
- GPU 总数、每节点卡数、亲和组大小和 TP 上限。

### 明确排除

- 存在慢卡、慢网络、层切分不均衡或特殊 rank mapping。
- 模型无法在 `PP=1` 下放入显存。
- score 权重、搜索空间或 `active/bubble/micro` 定义发生变化。
- 需要把结论外推到 64 卡等未验证规模。

## 5. 部署动作

### 选择步骤

1. 校验上述召回条件；任一关键条件不满足时停止复用。
2. 用本页“核心定量规则”和来源公式复算候选，确认 v10 score 仍把 `1/8/4/1` 排在第一位。
3. 将 `PP=1,TP=8,DP=4,MBN=1` 作为第一轮 Evaluation 基线，而不是直接作为最终部署结论。
4. 按本页“最小对照集合”和“预期观测与验收标准”运行真实 Evaluation。
5. 只有通过本页验收标准后，才生成提升状态的更新提案。

### 第一基线

```text
PP=1, TP=8, DP=4, MBN=1, active_gpu=32
```

### 最小对照集合

```text
A: PP=1, TP=4, DP=8, MBN=1        # TP/DP 反事实
B: PP=2, TP=4, DP=4, MBN∈{1,2,4}  # PP、显存和 bubble 反事实
C: 至少一个 active_gpu<32 的候选  # 满卡假设反事实
```

来源没有给出可执行的 rank/group mapping，因此本页不补造。

## 6. 核心定量规则

### 当前可证规则

固定 `PP=1`、满 32 卡、`TP≤8` 和来源列出的因子候选时，选择：

```text
argmax[tp + 0.2×dp - 0.9×|tp-dp|] = (TP=8, DP=4)
```

| TP | DP | TP/DP 评分项 |
|---:|---:|---:|
| 1 | 32 | -20.5 |
| 2 | 16 | -7.4 |
| 4 | 8 | 2.0 |
| 8 | 4 | 5.2 |

### 规则与实例边界

- `TP=8,DP=4` 是当前候选集合中的最优实例。
- `TP:DP=2:1` 是该实例的比例描述，不是已经跨卡数、跨拓扑验证的通用规律。
- 当总卡数、TP 上限、候选因子或 score 权重改变时，必须重新计算，不能直接套用 `2:1`。

## 7. 作用机制

| 动作 | score 中的作用 | 尚未证明的真实部署机制 |
|---|---|---|
| 满 32 卡 | 消除 `-2×idle` | 计算收益是否大于新增通信成本 |
| `TP=8,DP=4` | 在当前离散候选中 TP/DP 评分最高 | TP/DP 通信是否真正优于对照 |
| `PP=1` | 避免 `-50×bubble` | 显存是否允许、深 PP 是否可能增益 |
| `MBN=1` | MBN 二次 penalty 为 0 | 真实吞吐、延迟和显存是否更优 |

因此，这四个动作目前是 score 行为，不是完整的硬件因果证据。

## 8. 证据

### Score 证据

- 来源给出了 v10 公式、第一候选和四组 TP/DP 评分对照。
- score 系统性偏向满卡、低 bubble 和 `MBN=1`。
- `micro` 的定义及其与 DP、MBN、global batch 的关系缺失，无法复算完整候选总分。

### 拓扑证据

来源只描述了带宽层级，没有提供定量通信数据，也没有证明候选的 rank/group 映射。任何“TP=8 对齐单节点”的解释都只能作为 Wiki 补充假设。

### Evaluation 证据

无。缺少 latency、throughput、peak memory、TP/DP 通信时间、跨亲和组同步时间和重复实验波动。

## 9. 预期观测与验收标准

### Score 侧

- 在完全相同的候选约束下，应复现 `1/8/4/1` 的第一排名。
- 如果无法复现，先检查搜索空间及 `active/bubble/micro` 定义，不进入 Evaluation 结论。

### Evaluation 侧

在测试前定义最小有效提升阈值 `δ`。只有同时满足以下条件，才认为经验命中：

```text
推荐基线相对所有最小对照候选的目标指标改善 ≥ δ
并且无 OOM、稳定性退化或不可接受的通信/尾延迟增长
并且重复实验结果超过测量波动
```

来源没有给出 `δ`，因此当前不能判定命中。

## 10. 失效边界与回退

| 失效信号 | 判断 | 回退动作 |
|---|---|---|
| score 排名无法复现 | `1/8/4/1` 不再第一 | 检查定义并重新搜索 |
| `PP=1` OOM | 模型无法放入显存 | 选择满足显存约束的最小 PP |
| 少卡候选更快 | 通信收益超过满卡收益 | 停止满卡默认，记录反转边界 |
| `4/8` 或其他因子对更优 | Evaluation 反驳 score 排名 | 更新 TP/DP 条件分支 |
| MBN 增大更优 | 吞吐收益超过延迟/显存成本 | 扫描 MBN 并更新边界 |
| 出现慢卡或拓扑改变 | 召回条件不匹配 | 使用异构场景经验或重新分析 |
