# ScoreExpert 经验库增量演示

这组文件专门展示四个场景如何从来源材料进入经验库，以及每次新增场景时经验候选如何经过审查。它不替代 `raw/` 的不可变来源，也不把演示快照自动写成 `active` 正式经验。

## 阅读顺序

1. `01-source-cards/`：按同一模板整理的四份场景源文档。
2. `02-initial-library.md`：只使用正常卡和单张慢卡建立初始经验库。
3. `03-after-two-slow-gpus.md`：加入两张慢卡后的筛选前、审查过程和筛选后快照。
4. `04-after-four-slow-gpus.md`：再加入四张慢卡后的筛选前、审查过程和筛选后快照。
5. `05-evolution-summary.md`：三次快照的差异、知识框架和自检结果。

## 四层知识框架

```text
不可变来源 raw/
    ↓ 来源忠实整理，不删 score 推导
场景源文档 outputs/.../01-source-cards/
    ↓ 提取所有候选，保留来源位置和证据类型
审查队列（经验 / 证据 / 待验证 / 拒绝）
    ↓ 只有通过经验门槛的候选进入阶段快照
知识页 concepts/ + 状态、边界和验证计划
```

各层职责如下：

| 层 | 保存内容 | 是否能直接作为部署经验 |
|---|---|---|
| 来源层 | 原始场景、最优解、score 代码、原始总结 | 否 |
| 场景源文档 | 四个场景的统一模板整理与来源定位 | 否 |
| 审查层 | 候选、判定、拒绝理由和去向 | 只有通过项可以 |
| 经验层 | 可召回规则、动作、机制、观测、边界、状态 | 仍受状态限制 |

## 经验审查门槛

每条候选依次通过以下检查：

1. **来源可追溯**：能定位到 raw 来源和场景。
2. **触发条件具体**：至少包含慢卡数量/位置、拓扑或模型约束。
3. **部署动作可执行**：说明 PP/TP/DP/MBN 或 rank/group/stage 怎么设置。
4. **机制不是 score 同义反复**：必须说明同步组、流水线、replica skew、显存等部署机制；“因为 score 高”不算机制。
5. **预期观测可检查**：至少给出 latency、throughput、stage time、group time、replica skew、OOM 等指标之一。
6. **失效边界明确**：说明什么变化会停止复用。
7. **有新增价值**：不是已有经验的空泛改写或参数重复。
8. **证据与状态匹配**：score-only 进入证据层；缺少 Evaluation 的规则保持 `unverified`；只报告 Evaluation 胜者但无原始指标时最多为 `partially_supported`。

审查结果只有四类：

- `ACCEPT_EXPERIENCE`：进入经验快照，但仍携带状态。
- `EVIDENCE_ONLY`：保留为“为什么被打高分”的证据，不算部署经验。
- `KEEP_FOR_VALIDATION`：命题具体但证据不足，进入验证计划。
- `REJECT`：空泛、重复、不可执行或无法追溯，不进入知识库。

重要边界：筛选只决定候选进入知识库后的角色，不删除来源里的明确结论。纯 score 结论仍保留在场景源文档和证据层。

## 当前演示结论

- 初始库保留两条场景化经验：正常卡基线选择、单慢卡局部隔离；二者均为 `unverified`。
- 加入两张慢卡后，新增“跨亲和组分散时从隔离切换到无 PP 均衡”的经验，状态为 `partially_supported`。
- 加入四张慢卡后，新增“一节点一慢卡时让 DP replica 结构对称”的经验，状态为 `partially_supported`。
- `PP=1/MBN=1` 的强 score 偏好、`TP=8/DP=4` 的弱 score 偏好等只作为证据；score 未读取慢卡数量和位置，不能作为慢卡部署机制。
