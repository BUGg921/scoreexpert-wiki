# 三阶段演化总结与自检

## 经验库如何演化

| 快照 | 输入场景 | 筛选后经验 | 新增的决策知识 | 状态 |
|---|---|---:|---|---|
| 阶段 0 | 正常卡 + 单慢卡 | 2 | 正常场景先选验证基线；局部单慢卡尝试隔离 | 2×`unverified` |
| 阶段 1 | + 两张跨亲和组慢卡 | 3 | 从局部隔离切换到无 PP 均衡，并显式监控 replica skew | 新增 1×`partially_supported` |
| 阶段 2 | + 四张均匀慢卡 | 4 | 让每个副本具有相同慢卡结构，同时区分均衡与绝对性能 | 新增 1×`partially_supported` |

## 参数相同不等于经验相同

两张和四张慢卡都得到 `PP=1,TP=8,DP=4,MBN=1`，正常卡也使用这个参数作为第一基线，但三条经验不能合并：

| 场景 | 核心目标 | 主要观测 | 失效条件 |
|---|---|---|---|
| 正常卡 | 验证 score 排名是否对应真实性能 | score、通信、吞吐、显存 | 慢卡出现、score 改变、对照更优 |
| 两慢卡 | 避免多个慢点进入深 PP，并识别快慢副本等待 | replica skew、等待比例 | 慢卡集中、skew 过大、深 PP 更优 |
| 四慢卡 | 让四个副本的慢卡结构对称 | replica 均值与方差 | 位置/速度不对称、绝对性能不可接受 |

所以经验主键应近似为：

```text
场景条件 + 部署动作 + 作用机制 + 验收指标 + 失效边界
```

不能只用参数元组作为经验主键。

## 被筛掉的典型内容

| 类型 | 示例 | 处理 |
|---|---|---|
| 空泛 | “选择更合理的并行策略” | `REJECT` |
| 纯 score | “因为该候选 score 最高，所以部署它” | `EVIDENCE_ONLY` |
| 过度外推 | “正常卡永远满卡”“四慢卡固定 1/8/4/1” | `REJECT` |
| 边界伪规律 | “MBN 越大越好” | `REJECT`，保留 64 为搜索上界证据 |
| 重复参数 | 再次保存 `1/8/4/1` 而无新触发和机制 | `REJECT` 或并入证据 |
| 可证伪但缺证 | “对称映射会降低 skew” | `KEEP_FOR_VALIDATION` |

## 被保留但不算经验的 Score 知识

- 正常卡 v10 score 为什么偏向满卡、低 bubble、当前候选中的 `8/4` 和 `MBN=1`。
- 单慢卡两套 score 为什么把 TP/DP 视为成本，并把 MBN 推到搜索上界。
- 多慢卡 score 为什么强偏好 `PP=1,MBN=1`，而只弱偏好 `TP=8,DP=4`。
- 多慢卡 score 没有读取慢卡数量、位置和速度，因此不能解释两卡/四卡差异。

这些内容有诊断价值，会保存在证据层，但不能单独回答“下一次这个硬件场景应该怎么部署”。

## 自检清单

- [x] 四个场景各有一份同模板源文档。
- [x] 四份源文档都包含场景、最优解、score、为何得分、来源总结和证据边界。
- [x] 初始库只使用正常卡和单慢卡。
- [x] 两慢卡和四慢卡分别作为后续增量，不提前泄漏。
- [x] 每次增量都保存筛选前候选、逐条判定、筛选后快照和数量变化。
- [x] 纯 score 内容没有被删除，但被降为证据而非经验。
- [x] `MBN=64` 明确标记为搜索上界候选。
- [x] `TP=8,DP=4` 的 0.28 分弱偏好没有写成通用规律。
- [x] 两张和四张慢卡的相同参数没有被误合并为同一经验。
- [x] 没有把缺少原始指标的“Evaluation 最优”升级为 `active`。
